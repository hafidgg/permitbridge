## What each page actually shows (built exactly per spec, nothing invented)

- **Header**: source → destination, "Registered Nurse License Transfer" subtitle, transfer-mechanism badge, an evidence-status badge (Fully/Partially Supported, Limited Evidence — reusing the existing `success`/`warning`/`destructive` Badge tokens already in the design system), and a verification-date range (explicitly showing a *range* when fields were checked on different dates, never implying one single verification date for the whole page).
- **Blocked notice** (California→Texas only): a visible amber/red banner reading "Some critical requirements are still awaiting authoritative verification," with no internal implementation detail (no source IDs, no code terms) — just an honest, actionable statement.
- **Quick Answer**: 4-5 short statements (mechanism, exam required?, application required?, cost) generated by directly reading `TransferRule` field values — verified in code review that no string is hand-written prose about a specific fact; every claim traces to a field.
- **Critical Requirements / Additional Details**: two sections, 18 fields total, each rendered by the same `RequirementRow` component reading directly off `VerifiedField` — value, status badge, source link + title, "Secondary Source" badge when applicable, checked-date, confidence %, and for conditional requirements, a structured "This requirement applies if: [conditions]" block (never flattened to yes/no).
- **Trust & Methodology**: a static, factual 5-point explanation matching exactly what the verification system actually does (no "100% accurate" language).
- **Internal navigation**: links to the live `/profession/nurse` page, live `/state/{slug}` pages, and the other 4 transfer pages — **each conditionally rendered only if the target page actually exists** (see Issue #1 below).

## Issues discovered (and fixed) during this phase

1. **Broken internal links, caught before shipping**: the knowledge base's `registered-nurse` profession slug and its 50-state coverage don't match the *live* site's simpler existing schema (`nurse` profession slug, only 5 states). An early draft linked to `/profession/registered-nurse` (doesn't exist) and, for Illinois→Georgia specifically, `/state/illinois` and `/state/georgia` (neither exists on the live site). **Fixed**: every internal link is now computed against the live site's actual data (`getAllStates()`/`getAllProfessions()`) and conditionally omitted — never guessed — when no real target page exists. Directly tested that Illinois→Georgia's page would correctly show zero state quick-links for its own source/destination states, since neither is in the live 5-state set.
